# Pocket DSH

> *"Curiouser and curiouser!"*

DeepSeek Harness 的轻量移动端伴侣插件——**快、顺滑、跟手**是这条线唯一的产品哲学：微信提醒点链接秒开、发送即刻上屏、流式不抢滚动、重启后自动回连。

本仓的包名是 `dsh-pocket-glide`，GitHub 仓库是 [Gaudi-XIX/dsh-pocket-glide](https://github.com/Gaudi-XIX/dsh-pocket-glide)；它与 GitHub 上的 `shaobeichen/dsh-pocket` 是互不相干的两个项目，而 npm 上的裸名 `dsh-pocket` 又是别人发布的第三个包（v2.12.0，GPL-2.0）——别装错。

它的核心定位非常明确：**不在手机端复刻桌面端的全套系统配置与复杂文件树，只保留移动交互的核心闭环——发送提示词、查看流式回复、审批工具权限、管好 DS Bot 团队与远程运维。**

---

## 为什么做 Pocket：设计取舍

DSH 在电脑端执行重构排查、代码修改或跑单测时，任务往往需要持续十几分钟。在这些长任务运行期间，用户离开电脑后，最关键的需求只有两点：
1. **随时发送指令**：离开工位时，随时在手机上新建或切换会话、随时换新会话的模型，输入新的提示词，让电脑端在本地代码库中继续执行；
2. **处理交互门禁**：当 Agent 遇到敏感工具权限需要授权，或调用 `ask_user_question` 等待人工决策时，在手机端及时点击确认放行，防止长任务一直挂起空等。

如果把桌面端全套的模型配置、深层设置项和完整文件目录全部搬到移动端，在窄屏触屏上操作繁琐且极易误触。

Pocket 的选择是做明确的减法：桌面端负责完整的代码生产与系统管理，手机端只做轻量、低干扰的随身交互。**这个减法是这套顺滑的来源，也是它的代价**（见下面「我们有什么、没有什么」的第四象限）。

## 我们有什么、没有什么（四象限）

### 一、人无我有

* **「推送—直达—重启自愈」闭环**：任务完成或需要输入时，Webhook（微信 Server酱 / WxPusher / Bark）把消息推进手机通知；点通知里的链接**直接落回会话页面**；电脑需要重启时手机上一键触发优雅重启，重启后随机分配的 Cloudflare 临时隧道新地址**自动推送回手机**——点新链接接着用，永不需要手动找地址；
* **手机上的 DS Bot 团队页**：主页右下角一键切进 DSBOT——Bot 成员私聊、群聊、工具审批卡、成员运行状态（谁在跑什么工具、哪个群在讨论中）全部在手机上完成，群里随手发言；Bot 的私聊交班了就自动向更早的段落回填，一年的历史不断层；
* **过渡页秒切**：主页与 DSBOT 两边互跳各有同风格的四步过渡卡（读取工作区/会话列表/会话消息 ↔ 读取 BOT 列表/BOT 消息/群聊），切换的瞬间桥已经在预读对面页面的数据（`page.cue` 预热），落屏即有内容；
* **壳字节预算纪律**：整个手机壳（HTML+CSS+JS）钉死在逐 locale 的字节预算内（`test/mobile-assets.test.js`），谁加东西谁就得先省出等量字节——这是「在微信 WebView 里秒开不闪退」的工程保票。

### 二、人有我优

* **秒开跟手**：内容寻址的壳脚本长缓存、列表后台预热会话尾包、上次的 Bot 名册落盘即画（后台再刷新）、发送**乐观上屏**（点了发送字就在屏上，失败才撤回）——点进任何地方都不应有白屏等待；
* **流式上滑不强行拽底**：AI 高速打字时，用户一旦向上滑动屏幕查看上下文，贴底逻辑自动解除，绝不抢夺视口；读完轻点向下箭头平滑回底；新消息只增量落屏，不打断正在进行的阅读和选择；
* **软键盘动态高度避让**：键盘唤起时输入框精准上浮，不遮挡输入区、不顶碎布局；
* **单折叠卡直播**：思考链与工具调用统一收拢在单张折叠卡内平滑更新，无跳屏抖动；子代理任务折叠行直播运行态；
* **消息时间的三层钟**：今天显示时刻、同年补月日、跨年补全年——列表、会话、更早分段统一一套（`HH:MM` / `M月D日 HH:MM` / `Y年M月D日 HH:MM`）。

### 三、大家都有，我们也完整支持

* **连接与网络**：局域网扫码直连（0.0.0.0:43127，遇冲突自动让号）；Cloudflare Quick Tunnel 公网加密穿透（Host 出站，无需端口映射）；
* **会话与交互**：多会话管理（新建/切换/重命名/删除，置顶）；长文本、图片与通用文件上传；SSE 流式输出、思考过程折叠、Markdown 与代码块高亮；敏感写操作一键放行/拒绝；`ask_user_question` 选项交互；
* **外观与形态**：深色模式（跟随系统 + 手动切换）；PWA「添加到主屏幕」全屏运行；中英双语。

### 四、我们确实没有（喜恶同源：顺滑是减法买来的）

以下不是没来得及做，是**故意不做**——每一项都在给「快、轻、跟手」让路：

* **不做全量桌面系统配置与插件管理**——环境变量、profile 编排、插件安装属于桌面端职责，窄屏上配置易误触；这类设置**需要回到电脑前**完成，这是本设计哲学最大的代价，明说；
* **不做工程文件树浏览与在机代码编辑器**——手机端定位是需求输入与门禁放行，代码 diff 审查留在电脑大屏；
* **不自建中心化云端服务器与账号系统**——纯本地运行 + 点对点出站穿透，提示词与代码不在任何第三方云端留存；
* **不打包原生 App（APK / IPA）**——纯 Web 链接点开即用，免安装免发版审核，微信内秒开秒关。

## DS Bot 团队页（`/bot`）

主页右下角的机器人按钮进入，是手机上对 DS Bot 团队的完整视窗：

* **待处理**：Bot 的工具审批卡在手机上**允许 / 拒绝**；桌面才能回答的卡片如实标注，不出借按钮；
* **群聊**：每个群一行——成员数、最后一条发言预览、「讨论中」运行标记；点开即聊（消息直写该群的 Session）;
* **成员**：每个 Bot 一行——头像、角色、主 Bot 徽标、等待模型选择的「等模型」标记、正在运行的工具（「正在 bash」+ 忙态描边）；点开即进入该 Bot 的私聊；
* **历史不断层**：Bot 私聊是一段一段交班的，打开只读最新段会让一年的记录看起来没发生过——页面自动向更早的段落回填，分段处以带时间戳的分隔线标出。

## 快速使用

### 1. 安装与启用
本仓是**本地插件**，没有发布到任何包市场，装法只有一条：在仓库根目录先跑 `node tools/install-to-profile.mjs --dry-run` 看它要改什么，确认后跑 `node tools/install-to-profile.mjs` —— 它只改 DSH profile 的 `package.json` 两处（依赖指向本仓、`dsh.profile.bundles` 加一条），改前自动备份，加 `--install` 会顺带跑 `pnpm install`；装完重启 DSH 生效。

### 2. 扫码配对
1. 点击 DSH 桌面端侧边栏的 **Pocket** 图标打开配对面板；
2. 手机打开相机或微信扫码即可直接访问（支持在 Safari/Chrome 中「添加到主屏幕」全屏使用，也支持在微信内直接打开）。

### 3. 配置外带通知（可选）
在桌面配对面板中填入推送凭据（微信 Server酱 / WxPusher / Bark）：
* 任务完成或等待输入时接收手机震动提醒；
* 触发远程重启后，新生成的公网地址自动推送至手机。

## 运行环境

* **宿主依赖**：DeepSeek Harness `v0.2.0-rc.1` 及以上，Node.js `^22.19.0 || >=24.0.0`；
* **架构形态**：宿主进程内加载（In-Process Cordis Plugin），不是独立进程，随 DSH 启动而起、随退出而止，无独立后台常驻守护进程；
* **改动生效**：改 `lib/**` 或新增 bundle 必须**重启 DeepSeek Harness**（junction 是活的，插件随宿主启动装载）；手机端还要**完全关闭重开**页面才能拿到新壳，下拉刷新拿到的仍是旧壳；
* **架构细则**：形态、桥的宿主内生命周期、目录与关键常量见 [`docs/SPEC-ARCHITECTURE.md`](docs/SPEC-ARCHITECTURE.md)；
* **网络端口**：默认监听 `0.0.0.0:43127`（占用自动顺延至 `43128`，支持通过 `DSH_MOBILE_PORT` 环境变量显式指定）；
* **外网访问**：内置出站型 Cloudflare Quick Tunnel，无需公网 IP 与路由器端口映射。

> **版本与变更账**：逐版的对外变化（修复 / 契约变更 / 已知边界）见 [`CHANGELOG.md`](CHANGELOG.md)，其最新一节对应当前 `package.json` 的 `version`；更细的逐笔施工账在 `git log` 与 flow change 卡里。本仓从 `0.2.0` 起维护这份变更账。
