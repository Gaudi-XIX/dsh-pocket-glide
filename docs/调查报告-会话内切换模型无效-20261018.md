1. **端到端链路是通的**：宿主侧有不可磨灭的成功痕迹（每次成功 `selectModel` 必 append 一条 `model/selection`，不去重；`dsh-api-session-controller/lib/index.js:312-313`），10-18 全天抓到 18 条，其中 **2 条是会话内切换**；被查到的那条切换，**下一个请求真的用了新模型**（`session-610b0994` seq=1548 23:27:43 → seq=1559 23:32:53 的 `request/header`）。所以「宿主不受理 / 契约字段名不匹配 / 端点写错」这三个方向**全部排除**。

### 7.1 机制链（代码可证，不需要用户再复现一次）

`session/selectModel` 的宿主通路完好（§Q1 已实证 18 条 append、2 条 seq>3 且下一请求真换模型），手机侧日志零命中 ⇒ **RPC 根本没发**。而页面在「草稿态」与「运行中会话」两种状态下**共用同一套显示逻辑、同一句成功文案**，四条事实叠加即构成「看着切了、实际没动」：

1. **草稿缓冲无条件优先于实时投影**（HEAD `79b0f85`）：`draftModelSelection(){if(draftPending&&draftPending.model)return {...draftPending.model}; return modelSelectionOf(streamProjections)}`（HEAD:1706）、`draftAgentPreset()`（HEAD:1705）同形 —— **不问有没有活动会话**。
2. **面板显示与 `modelCatalog.current` 都被缓冲污染**：`renderSessionSettings()`（HEAD:1386）首行 `const current=draftModelSelection()||currentSelection()`，preset 字段用 `(currentPreset||draftPending&&draftPending.preset)`；`openSessionSettings()`（HEAD:1451 → 现 :1454）还有 `const selected=draftModelSelection();if(selected)modelCatalog.current=selected`。⇒ **进入运行中会话后打开设置面板，模型行显示的是草稿里选过的那个**。
3. **缓冲只有两个丢弃点**：`draftPendingDrop()`（现 :1704）仅在 `applyDraftPending()` 的 finally 与 `startDraftChat()` 首行被调用（`grep draftPendingDrop` 全文件仅此两处）。⇒ 用户在草稿态点过一次模型/预设、而那条草稿**没有发出去**，缓冲就一直留着，随后污染任何运行中会话的面板。
4. **草稿点选冒充实况**：草稿态走 `selectModel` 的 `if(!activeSession){draftSetModel(entry);return}`（HEAD:1453），只写缓冲、当场不发 RPC；而 `draftSetModel`/`draftSetPreset`/`draftSetPermission`（HEAD:1712/1715/1716）弹的是 **`showToast(L.settingsUpdated)`＝与真切换同一条「会话设置已更新」**。用户原话「**更新**切换模型好像不行」与该字符串同形。

⇒ 综合判定：**病根 = 草稿态与运行中会话共用显示与同一句成功文案**，不是宿主、不是缓存盖回、不是契约。§二 列的 4 条静默路径中，第 1 条（草稿态不发 RPC）与第 4 条（早退）在此被提升为**可证机制**；§三 要求的「用户时刻」对本 bug 不再必需（仍可作交叉验证）。
