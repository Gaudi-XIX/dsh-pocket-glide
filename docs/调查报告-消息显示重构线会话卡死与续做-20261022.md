## 三、这次接着做了什么（提交 `4f7ac3b`）

### A. 「每次返回主页再进去，时间刷新成 1 秒」
- 根因：返回主页再进会话是**整页重建**，页面把整段日志重新喂给 `visibleMessages` / `updateRunning`；跑着的回合被重新见到一次它的 `turn/start`，而 `noteTurnBoundary` 每次都在那一刻 `turnElapsedAt=Date.now()` ⇒ 同一个回合每进一次页面就从 0/1 秒重来。
- 改法（只借宿主“跨度”，不跨机器比较绝对时间）：`turn/start` 记下记录自带时间戳 `turnElapsedHostStart`；每次轮询用「手上最新记录的时间戳 − 起点时间戳」得到宿主机已走时长，再 `turnElapsedAt = Date.now() - span` 由本机时钟续走；**只在宿主跨度大于本机已走时长时前进**，故轮询重放同一批记录不会把显示往回拨。`turn/end` 同样按两个宿主戳之差记账（替代原先 `Date.now()-turnElapsedAt`，不再受轮询间隔影响）。
- 为什么安全：跨机器参与的只有**两个宿主戳相减得到的时长**；一次「宿主绝对时间 − 手机墙钟」的减法都没有——那条比较正是 10-13 把状态永久钉死的成因（见 `lib/pages.js:1298-1306` 旧注）。

### B. 「排队/插入的消息位置依然不对」
- 根因：插入消息（steer）被宿主塞进**已经在跑的回合**里，seq 落在该回合内部；旧实现靠 `orderUserBubblesByTime` 按时间戳搬家，遇到无时间戳的过程卡会把它抬到过程卡之上（用户 09:22 原话「他把我后面补充的消息，就顶到了思考条和工具条之上去了」；15:10 复述「位置依然是不对的」）。
- 改法：`visibleMessages` 给每个内容块记下自己的 `seq` 与宿主时间戳；落在这个回合里的 `user/message` **按同一把尺子插到对应位置，并在插入处切断过程卡**（气泡上方一段、下方一段）。内联气泡标 `_inTurn`，不再交给外层的时间戳搬家；**跨回合的顶层气泡仍保留 2026-10-19 的“回到写下它的时刻”契约**。
- 真实会话复验（`session-7ad97a26` turn 6，seq 5268→7335，用页面自己的 `visibleMessages` 跑）：

```
USER 08:19:51 → 过程卡 → USER 09:06:41 → 过程卡 → USER 09:08:07 → 过程卡 → USER 09:22:31 → 过程卡 → 回答 10:47
```
  改前是「USER 09:06 被抬到过程卡之上、其余插话落在最后一条回答之后」。
