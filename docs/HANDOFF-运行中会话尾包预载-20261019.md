## 1. 症状与根因（一句话）

主页给「运行中」的会话**预载尾包时一律跳过**，于是点进那条会话时 `tailCache` 里没有它的包，`paintInstantSession` 画不出内容，只能落到骨架屏「正在加载消息」，等一次全量 `session.history` 才出内容。

用户原话（2026-10-18，m00002）：**「点进正在跑的会话，显示正在加载消息」**；期望：**「预载一屏消息，或者至少一轮最后一个回复」**。

### 证据链（`lib/pages.js`，行号为基线 HEAD 读法）

- `lib/pages.js:1651` — `requestVisibleTails(host)` 的循环体内：

  ```js
  const s = byId.get(id);
  if (!s || taskState(s) === 'running') continue;   // ← 运行中的行在这里被整个丢掉
  ```

  这是**唯一**一处排除点。`s` 缺席（boot 快照没给这个会话行）也一起被跳过，这一条**是对的、要保留**。

- `lib/pages.js:1644` — `const tailCache=new Map(),tailArmedAt={},tailPending=new Set(),tailFailed={}`。
- `lib/pages.js:1656` — 只有真拿到包才 `tailCache.set(id,extracted)` 并 `tailArmedAt[id]=stamp`。
- 绘制侧：`paintInstantSession` 的 `tailCache` 分支从预载包画首屏（用户 2026-10-15 m00002 之后 0.4.47 `cdaec5c` 立的能力，「预取尾包留记录并接入首屏——点进会话不空白」）。cache 里没有 → 该分支不成立 → 骨架屏。

### 桥侧不设限（重要，决定了这只是一行页面改动）

`lib/bridge.js:6247` 的 `session.tails` 处理器**不筛运行中会话**：它对请求里每个 id 都从 `cachedSessionList`（10s 窗口）取行、缺失或没有 `asOfSeq` 时**强制刷一次 list**，再按 `{maxMessages:8, turnWindow}` 两条形状翻 `session/page`；单会话失败写成 `{error}` 标记而不失败整包。相关常量：`TAILS_MAX_SESSIONS=30`（`lib/bridge.js:146`）、`TAILS_CONCURRENCY=4`（`lib/bridge.js:147`）、`TAIL_PAGE_MESSAGES=8`（`lib/bridge.js:148`）。

⇒ 「跳过运行中会话」**纯粹是页面侧的判断**。桥不用改，页面改一行即可闭环。

## 8. 风险与回退

| 风险 | 量级 | 处置 |
|---|---|---|
| 运行中会话 `updatedAt` 频繁变动 ⇒ 每次主页绘制都会重新预取它的尾包 | 低。主页档轮询 `LIST_POLL_MS=60000`（`lib/pages.js:971`），且预取只随 `renderWorkspaces` 的绘制走；受 `tailPending` claim、`TAIL_CACHE_MAX=64`、`TAIL_RETRY_MAX=3`、桥 `TAILS_MAX_SESSIONS=30` 四重封顶 | 若真机观察到过量：把「运行中行」的门槛收紧成「只拉首屏前 N 行」或「包已在缓存里就按 `tailArmedAt` 不再重拉」——**先量再改，别预防性加门禁** |
| 预取回来的包是「上一轮」的内容，与流里正在长的那轮不一致 | 低。包只用于点进去那一下的首屏铺设，随后 SSE/`loadHistory` 按 seq 合并 | 无需处理；验收第 3 条本身就是判据 |
| 用户真实诉求可能不是「预载」而是「别显示『正在加载消息』这句话」 | 中 | 见 §9 乙案 |

**回退**：改动只有 1 行代码 + 1 处注释，`git revert` 该提交即回到现网行为；无数据迁移、无 schema、无配置。测试侧同提交回退即可。
