## 一、已定的两件事

### A. 公网地址不要再带令牌

- 现状：电脑端配对页/二维码编的是 `<隧道域名>/pair?token=<pairingToken>`（`bridge.js:2551`），
  局域网那份是 `http://<ip>:<port>/pair?token=...`（`:2553`）。
- 已证事实：**公网路径上这个 token 不省 PIN** —— `/pair` 校验 token 通过后仍然渲染 PIN 页
  （`bridge.js:4007-4008`）；只有**局域网**路径才是"校验通过直接发 cookie、免输 PIN"（`:4000-4004`）。
- 所以公网去掉它**没有功能损失**，反而少把一次性配对凭据暴露到 URL 里（会进聊天记录/剪贴板历史）。
- 改法：把公网那两处（显示的地址文本 + 二维码内容）改成裸 `https://<域名>/`；**局域网保留 token**
  （那是它免 PIN 的唯一机制，删了是降级）。`/pair` 那条路由本身保留不动——老二维码还要能用。
  注意：去掉后未配对手机打开裸地址会先进 `/consent`（连接须知），这条路 0.4.24 已修好落档，不会再死循环。

### B. 诊断模式做成产品能力

- 用户 14:07：「可以做成产品能力」。
- 设计（最小）：电脑端「设备与通知」面板加一个**诊断模式**开关，存进设置档
  （`mobile-bridge-settings.json` 的 notify 同级新键 `diagnostics`）。开关为**开**时：
  ① 配对页显示的公网/局域网地址、② 二维码内容、③ 微信推送的地址，三者一律追加 `?probe=1`。
  手机侧**不需要新代码**：0.4.25 的页内埋点本来就是"URL 带 `?probe` 或 localStorage 在 6 小时期内"才动。
  **已实现的半截**：`diagnosticsProbeEnabled()` 读设置档 `diagnostics.probe`（默认关），
  `pairingUrl` 公网分支与 `ensureTunnelForInbound` 的地址都已按它追加 `?probe=1`。
  **未实现的半截（剩这一件）**：桌面面板的开关控件 + 保存通道。锚点：
  面板 HTML 在 `lib/pages.js:2272` 的 `panelSectionsHtml`（`#deviceExtras` / `#notifyPanel` 里插一行），
  保存走 `lib/bridge.js:3708` 那条 `POST /desktop/notify` 的邻居（新 `POST /desktop/diagnostics`，
  照 `:3868` 的 `tunnel/config` 写法：读 body → `settingsStore.save` → 回快照），
  并把 `snapshot()` 里回一个 `diagnostics: { probe }` 给面板回显。

- 代价与边界（要写在 UI 文案里）：
  - 开着诊断 ⇒ 手机每滑动 1.5 s 就往 `pocket.log` 回传一批，日志会涨、手机多耗一点流量；
  - **换隧道域名（每次重启）后必须重新用带 `?probe` 的链接打开一次**：localStorage 按 origin 隔离，
    旧域名的凭据带不过去（判据 `docs/F真机判读-20261011.md` §9）；
  - 默认必须**关**，且这是产品默认，不做"开机自动开"。
